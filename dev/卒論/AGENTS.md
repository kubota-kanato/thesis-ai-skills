# 卒論の作業場所

本人はこのフォルダを VS Code で開き、ファイルを見ている。一覧や記録は Markdown で書く。Excel のファイルを作らない。

## 研究テーマ

論文を探すときの判断と、論文ごとの位置づけは、この記述を基準にする。本人が書き換える。

- 題目：{卒論の題目}
- 問い：{何を明らかにしたいか}
- 地域・試料：{調査地域、地層、試料}
- 手法：{使う分析・測定}
- 関わる分野の語：{日本語と英語の検索語}

## フォルダの分け方

```
卒論/
├── AGENTS.md      ← このファイル
├── 文献一覧.md     ← 論文の台帳。paper スキルの refs.py index が作り直す
├── レジュメ/       ← ゼミ発表のレジュメ
└── 論文/
    └── {状態}_{題名}/   ← 1本1フォルダ。状態は 未入手・未処理・処理済み
```

## 作業ごとにスキルを使う

| 頼まれたこと | スキル |
|---|---|
| 論文を探す、PDFを集める、解説・AIメモ・日本語訳を作る、引用文献リストを作る | `paper` |
| 卒論・予稿・レポートの文章 | `paper-writing` |
| ゼミのレジュメ、まとめ資料 | `doc-design`（レジュメは `レジュメ\` に置く） |

## 作業したら台帳を更新する

論文PDFを置いたとき、解説を作り終えたときは、`refs.py index` で文献一覧.md とフォルダ名を更新する。
論文の位置づけ（`支持する`・`反する`・`手法の参考`・`背景`）は、文献一覧.md の位置づけ列に書く。

## 論文の内容を説明するときは、原文の場所を添える

- 主張にはページ、節、図表番号を付ける
- 観測・測定の結果、著者の解釈、外部の知識、自分の推測を分けて書く
- 数値、単位、年代、試料数は原文で照合する
- 図は、軸・凡例・単位・比較対象を示してから結論を言う
