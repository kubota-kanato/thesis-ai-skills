# 資料デザイン（HTML・2モード）

テンプレは **CSS 内蔵の単体 HTML**。**丸ごとコピーして中身だけ差し替える。**
CSS の値を書き換えない／新しいスタイルを書き足さない。これが崩れない唯一のコツ。

---

## 0. 先にモードを1つ決める。ここを飛ばさない

| モード | いつ使う | テンプレ | 色 |
|---|---|---|---|
| **読む資料** | 画面で読み返す。長さ無制限 | `read-3col.html`（既定。§2）<br>`read.html`（右に置くものが無いときだけ） | **藍1色＋朱1色を使う** |
| **印刷資料** | A4に刷って手元で見る。1〜2枚で完結 | `print.html` | **藍1色＋朱1色を使う** |

投影するスライドはこのスキルで作らない。

判断がつかないときは一言だけ聞く → 「画面で読む？　紙に刷る？」
**「資料を作って」「まとめて」としか言われていないなら、既定は読む資料モード。**

### 2モードは要求される数値が違う

| | 読む資料 | 印刷 |
|---|---|---|
| 本文 | 16px | 10.5pt |
| 行間 | 1.9 | 1.5 |
| 行長 | **34em（約34字）** | A4幅・余白15mm |
| 見出し | 24px（1.5倍） | 15pt（1.43倍） |
| 1画面の分量 | 制限なし | 1枚で完結 |
| 有彩色 | **藍・朱** | **藍・朱** |

混ぜると必ずどっちつかずになる。

## 1. 手順

1. モードを決める（§0）
2. 読む資料なら §2 の手順に従う。印刷資料なら `print.html` を丸ごと出力先にコピーする
3. 中身を差し替える。**足りない型は既存の型を複製する。CSS を書き足さない**
4. ブラウザで通しで確認 → §6 のチェック
5. レビューを頼まれたとき・作ったものを自分で点検するときは `antipatterns.md` を読む

---

## 2. 読む資料は3カラム（`read-3col.html`）で作る。これが既定

### 2-1. 3つの列の役割は決まっている

| 列 | 置くもの | HTML の場所 |
|---|---|---|
| 左 | 目次。本文の見出しへのリンクだけ | `<nav id="nav">` の `<a href="#s1">` |
| 中央 | 解説（本文）。資料の中身は全部ここに書く | `<main>` |
| 右 | 補足資料。本文を読みながら横で見たいもの | `<aside id="fig">` の中の札（`<div class="card">`） |

読んでいる章に合わせて、右の札が自動で入れ替わる。

次の3つはどれも誤り。

- 本文を3つに分けて、3つの列に流し込む。本文は中央に全部書く
- 右に本文の続きや、本文と同じ説明を書く。右の札を全部消しても、中央だけで話が通じるようにする
- 右を埋めるために、中身の薄い札を作る。置くものが無い章には札を作らない（直前の札が残る）

### 2-2. 右に置く補足資料は5種類。テンプレに見本が1つずつ入っている

| 見本の札 | 動くか | 中身 |
|---|---|---|
| 型その5 `data-card="c4"` | 動かない | 図・写真・地図・柱状図。原図を貼り、出典を書く |
| 型その3 `data-card="c2"` / 型その1 `id="gloss"` | 動かない | 早見の表（4行まで） / これまでに出た用語の一覧（読み進めると増える） |
| 型その4 `data-card="c3"` | 押すと答えが出る | 章末の確認問題 |
| 型その2 `data-card="c1"` | つまみで動く | 動かせる図。値を変えると線や数値が描き直される |

### 2-3. 動かない札を基本にし、動く札は理由があるときだけ使う

動く札（つまみで動かせる図）を使うのは、次の両方に当てはまるときだけ。

- 値を1つ変えると、結果が目に見えて変わる（例：地層の傾斜と走向から見かけの傾斜、堆積速度と層厚から年代、粒径と流速から運ばれるかどうか）
- その変わり方を見ることが、その章で分かってほしいことそのものである

当てはまらなければ、図・写真・表の動かない札にする。
論文の図や野外写真は、どれだけ大事でも動かない札に置く。描き直して動く図にしない。
動く札を作ったら、つまみを端から端まで動かして、図が崩れないか、数値が正しいかを確かめる。

### 2-4. 作る手順

1. `read-3col.html` を出力先へ丸ごとコピーする
2. 中央 `<main>` に本文を書く。章の見出しは `<h2 id="s1">`、小見出しは `<h3 id="s1-1">` のように、全部に `id` を付ける
3. 左 `<nav id="nav">` に、見出しと同じ順で `<a href="#s1">1. 見出し</a>` を並べる。小見出しには `class="lv3"` を付ける
4. 章ごとに、右に置く補足資料を決める。無い章は飛ばす
5. 補足資料がある章の見出しに `data-fig="c1"` を付け、右の札に同じ値の `data-card="c1"` を付ける。`data-label` は番号の並びに出る1〜2文字、`data-title` はホバーで出る説明
6. 札は、2-2 の見本のうち近いものを複製して中身を差し替える。CSS は書き足さない
7. 使わなかった見本の札を消す。型その2（動かせる図）を消したら、`<script>` の中の「図1　複利で2倍になるまで」のかたまりも消す
8. 見本の文が残っていないか探す。次の語が本文と右に1つも残っていなければよい：「資料のタイトル」「見出し」「本文。」「複利」「data-fig を付けると」
9. 画像を `img/` に置いたなら、渡す前に base64 で埋め込む（`irasutoya` スキル §5）
10. ブラウザで開き、窓を最大にして上から下まで読み、章ごとに右の札が替わるかを見る

### 2-5. 2カラム（`read.html`）にするのは、右に置くものが1つも無いときだけ

画面1〜2つ分の短いメモで、図も表も用語も無いときに使う。迷ったら3カラムにする。

論文の解説資料は `paper` スキルの `解説資料.md` に従う。あちらは `read.html` を元にし、右に原論文の図が自動で出る別の仕組みを使う。`read-3col.html` と混ぜない。

### 2-6. 幅

| | 下限 | 既定 | 上限 |
|---|---|---|---|
| 目次 | 180px | 236px | 360px |
| 右の札 | 440px | 472px | 760px |

境界をドラッグして変える。ダブルクリックで既定値に戻る。
中央は 624px（34em＋左右余白80px）を必ず残し、窓が狭いときは右から詰める。
3カラムになるのは窓の幅が 1332px 以上のとき。それ未満では札が本文の下に並ぶ。
ノートPCで札が下に回るときは、ブラウザを最大化するか `Ctrl` + `-` で縮小すると3カラムになる。

右の上限 760px には根拠がある。SVG は viewBox 420幅で、中の文字は9〜15単位。
472px のとき10単位の文字が約10px、720px で約16px になり本文と同じ大きさで並ぶ。

### 2-7. その他の仕組み

- 札に `data-always` を付けると、章で切り替わらず出たままになる。その中の行に `data-since="s2"` を付けると、その章を過ぎてから出る
- 右上の「固定」を押すと、スクロールしても札が替わらない
- 左の検索欄は本文の語を引く。当たった語が光り、Enter で次、Shift+Enter で前
- メディアクエリを足すときはファイルの末尾にまとめる。途中に置くと、後ろの素の規則に打ち消される

## 3. 読む資料モードの色と文字（`read-3col.html` / `read.html` 共通）

### 3-1. 色の割り当て（1色 = 1意味）

| 色 | 値 | 意味 | 使う場所 |
|---|---|---|---|
| **藍** | `#12457A` | 「たどれるもの・構造の目印」 | リンク／h2 の下罫／章番号バッジ／表のヘッダ下罫／サイドナビの現在位置 |
| **朱** | `#9A3412` | 「気をつけるところ」 | 注意ボックスの左罫とラベルのみ |

**この2色以外の有彩色を足さない。**足したくなったら、それは色ではなく構造の問題。

### 3-2. 色を使ってはいけない場所

- **本文の文字色**（`#1A1A1A` のまま）
- **見出しの文字色**（黒のまま。**テーマカラーで見出しを塗るのは典型的なアンチパターン**）。
  色をつけるのは見出しの**下の罫線**だけ
- **強調**。強調は太字だけで作る。色文字・下線・網掛けを重ねない
- 広い面のベタ塗り。淡い面（`--tint-a`）は callout の中だけ

### 3-3. 破ってはいけない2つ

1. **リンクには必ず下線を引く。**藍と本文の明度差は 1.79:1 しかなく、
   色だけでリンクだと分かる基準（本文に対し 3:1）を満たさない。下線が唯一の手掛かり。
   下線を省いてよいのはサイドナビと目次だけ（リンクしか無い場所なので文脈で分かる）。
2. **注意ボックスには「注意」というラベル文字を必ず置く。**
   藍と朱は、P型・D型・T型の色覚ではコントラスト比 1.1〜1.7:1 しかなく、
   明度では区別できない。色は補助であって、意味を担うのはラベルと左罫。

### 3-4. その他

- 行長 `max-width:34em` を外さない。表・コード・図だけ `52em` まで逃がす。
- callout は種類を増やさない。**「注意」だけ**。多用すると際立ちを失う。隣接して2つ置かない。
- 見出しは H1 を1つ、あとは H2 / H3。**H4 が要るのは大抵「1ページに詰め込みすぎ」のサイン**。
- 段落・見出し・箇条書きは**情報を担う語で書き始める**（読者は拾い読みする）。
- 全部を箇条書きにしない。箇条書きは項目間の関係を示さないので、関係が大事なら文章で書く。

## 4. 印刷資料モード（`print.html`）—— 色を使う。ただし背景は落ちる前提

色の割り当ては読む資料と同じ（藍＝構造、朱＝注意）。加えて紙固有の制約がある。

1. **背景色は印刷されない前提で組む。**`print-color-adjust` の既定は `economy` で、
   ブラウザとプリンタが背景を消してよいことになっている。印刷ダイアログの
   「背景のグラフィック」も既定オフのことが多い。
   → **白抜き文字（濃い地に白文字）を印刷モードで使わない。**消えると情報が丸ごと失われる。
   → 章番号バッジは**枠線＋濃い文字**にしてある。塗りに変えない。
   → 淡い面は「出れば嬉しい」程度。意味は**左罫とラベル**で担保する。
2. **罫線は 0.5pt 以上。**0.25pt 以下は再現保証がない。
3. **5%以下のグレーは消える。**画面用の極薄ゼブラ縞を紙に持ち込まない。
4. リンクは色をつけても意味がない（押せない）。**URL は脚注に文字で書く。**
5. 1枚に収まらないときは、**削るか2枚にする。縮小で詰めない。**
   本文 10.5pt は自分用のカンペの下限。人に配るなら 12pt 以上。
   （12pt 以下の日本語を太字にすると、漢字の字画が潰れて読めなくなる。）

## 5. 2モード共通

### 5-1. フォント

**ローカルの3段スタック固定。Web フォントは読み込まない**（渡した先のPCがオフラインだと崩れる）。
数字だけ別フォントにするのも禁止。

```css
"Noto Sans JP","BIZ UDPGothic","BIZ UDPゴシック","Yu Gothic UI",Meiryo,sans-serif
```

- **Noto Sans JP** … 本人PCに可変フォントで導入済み。ウェイトが連続で効く
- **BIZ UDPゴシック** … Windows 10 1809+ に標準バンドル。他PCでもこれで受け止まる
- **游ゴシックUI** … 実測で一番細く狭い（日本語10文字で 341px、BIZ UDP 408px、Noto 422px）。
  **先頭に置かない。**「文字が細い」と言われたら真っ先にここを疑う

**ゴシック体だけを使う。明朝体を使わない。**明朝は横画が極端に細く、小サイズの印刷で飛ぶ。

### 5-2. ウェイト

**500 / 700 / 800 の3段だけ。**本文 500、見出し・強調 700、表紙タイトルと大きな数字 800。
**600 は使わない**（游ゴシックに落ちたとき 700 と同じになる）。
線も細くしない —— 罫線は 2px 以上、表の上下は 2.5px。
印刷モードは pt で指定するので **0.5pt 以上**（0.25pt 以下はヘアラインで再現保証がない）。

### 5-3. 強調

**太字だけ。**日本語に斜体は存在しない（`font-style:italic` は字形を歪めるだけ）。
下線はリンクの記号なので強調に使わない。網掛け・色文字を重ねない。
1画面あたり強調は1〜2箇所まで。増えると強調でなくなる。

### 5-4. 表の罫線 —— 縦罫は「引かない」ではなく「要るときだけ引く」

**既定は横罫だけ**（上下を太罫、見出しの下を細罫）。セルは余白で分ける。
罫線が増えるほど、読み手の目は中身より線に行く。

**ただし縦罫を足す。次のどれかに当てはまるとき:**

- 列が **5つ以上**ある
- セルに**数値が並ぶ**（桁を縦に読ませる表）
- セル内が **2行以上に折り返す**
- **手で書き込む欄**がある（記録用紙・チェックリスト・実験の記入表）

この4つはどれも「余白だけではどの列の値なのか追えなくなる」場面。
実験の記入表を横罫だけで組むと、実験中に手を止めて列を数える羽目になる。
`read.html` / `print.html` では `<table class="grid">` にすると縦罫が入る。**CSS は書き足さない。**

足すときも**薄いグレー1本**。太い格子にしない。二重罫線は引かない。ゼブラ縞と併用しない
（罫線があるならゼブラは過剰。ゼブラは横に長い表で罫線を使わないときの代替）。


### 5-5. 図の扱い

- **matplotlib / mermaid / graphviz / plotly で描き起こさない。**
- 論文・資料の図は**原図を切り出して** `<img>` で貼り、`<figcaption>` に出典
  （著者・年・雑誌・図番号）を必ず書く。
- 用意できないときは `[図: ○○]` のプレースホルダを置いて、あとで差し替える。

**挿し絵は2モードとも使ってよい。**探し方・落とし方・単体HTMLへの焼き込みは `irasutoya` スキルにある
（自分で `<svg>` を書いて線画を組み立てない）。**どちらのテンプレも `.pic` を持っている**ので、
`<span class="pic"><img src="..." alt=""></span>` を段落の先頭に置くだけでよい（CSS は書き足さない）。
読む資料は本文の右に回り込んで行長 34em を削らない。印刷は見出しの脇に 20mm。

守るのは1つだけ。**絵に情報を担わせない。**
白黒コピー・画像オフ・読み上げのどれでも意味が通る状態にする。
絵を見ないと分からない情報があるなら、それは挿し絵ではなく図なので、`<figure>` に出典付きで置く。

利用条件と点数の上限は `irasutoya` スキル §4。

### 5-6. 日本語

- 日本語で足りる語をわざわざ英語・カタカナにしない（「手法」を「アプローチ」等。
  論文中の専門用語・略語はそのままでよい）
- 「〜することができる」→「〜できる」、「まず最初に」→「まず」。冗長表現と重言を残さない
- 一文は50字を目安に切り、長くても90字まで（`reading-load.py` は90字を超えた文を指摘する）。ただし**全部を同じ長さに揃えない**（読む資料の地の文のみ。
  手順書・チェックリスト・仕様は揃っているほうが正しい。→ `antipatterns.md` C-4）
- 主張の根拠・数値・前提を省いて言葉足らずにしない（減らすのは**要素数**であって説明ではない）
- 詳しくは `antipatterns.md` の「日本語」節

#### 読解負荷を実測する（読む資料・印刷資料のみ）

一文の長さや漢字の連続は目視では判定しにくい。出す前に測る。
**手順書は対象外**（短文と箇条書きは揃っていて正しい）。

```bash
python "$env:USERPROFILE\.agents\skills\doc-design\reading-load.py" read.html
```

HTML をそのまま渡してよい（タグと見出し・箇条書き・表は落として、地の文だけを測る）。
**パスは必ず引用符で囲む**（bashだとバックスラッシュが消えて `program not found` になる）。
標準ライブラリだけで動くので、追加インストールは要らない。

出るのはこの4つ。

| 指標 | 意味 |
|---|---|
| `sentence_too_long` | 一文が90字を超えた。切る |
| `kanji_run` | 漢字が7字以上連続。語の切れ目が読めるか確認する |
| `no_chain` | 「の」の連鎖。係り受けが追いにくい |
| `antithesis_repetition` | 「AではなくB」の反復。「Bです」で足りないか見る |

文長の分散・語彙の多様性・語尾の反復は**測らない**。「AIが書いたように見えるか」の指標であって、
読みやすさの指標ではないため。文の長さを揃えないために文を伸ばすと、かえって読みにくくなる。

指摘は「エラー」ではなく「疑いの提示」。直さないと決めたら理由を持って残す。

## 6. 出す前のチェック

**順番を守る。① 主張 → ② 構造 → ③ 強弱 → ④ 装飾。**
上が直るまで下に行かない。主張が空のまま色と余白を直すと、整った空の資料ができあがる。

### 全モード共通

**① 主張**

- [ ] **見出しだけを上から並べて読んで、話の筋が通るか**（通らないなら中身がない）
- [ ] 数字に出典があるか。**AIが出した数字を確認せずに載せていないか**
- [ ] 地の文が続く資料なら、lintで読解負荷を測ったか（→ §5-6）
- [ ] 図に出典が書いてあるか／描き起こしていないか

**② 構造**

- [ ] セクション見出しが本文の1.4倍以上あるか
- [ ] **推す1つがあるのに、等価に並べていないか**（本当に並列なら等価でよい。→ `antipatterns.md` A-9）
- [ ] **表の縦罫が、要る表に入っていて／要らない表に入っていないか**（§5-4 の4条件で判定）

**③ 強弱**

- [ ] 強調が太字以外（色文字・下線・網掛け）になっていないか
- [ ] 1画面あたり強調が1〜2箇所に収まっているか
- [ ] 本文が `font-weight:500` になっているか。600 を使っていないか

**④ 装飾**

- [ ] `fonts.googleapis.com` を読み込んでいないか（**あったら削る**）
- [ ] **フォントの先頭が `Noto Sans JP` か**（`Yu Gothic UI` が先頭だと細く見える）
- [ ] 明朝体・影・グラデ・ダークモードが入っていないか
- [ ] 挿し絵に情報を担わせていないか（**絵が出なくても意味が通るか**。→ §5-5）
- [ ] `--ink-3` を `#8A8A8A` に戻していないか（**AA 不合格。`#6E6E6E` が正**）

### 読む資料

- [ ] **有彩色が藍と朱の2色だけか**（3色目が入っていたら削る）
- [ ] **見出しの文字が黒か**（テーマカラーで塗っていないか）
- [ ] **リンクに下線が付いているか**
- [ ] 注意ボックスに「注意」のラベル文字があるか
- [ ] `max-width:34em` を外していないか
- [ ] callout が1ページに増えすぎていないか。2つ隣接していないか
- [ ] 中央だけで話が通じるか（右の札に本文の続きを書いていないか）
- [ ] 見出しの `data-fig` と札の `data-card` が全部対になっているか。札の無い章に `data-fig` を付けていないか
- [ ] 左の目次が、本文の見出しと同じ数・同じ順で並んでいるか
- [ ] 動く札は、2-3 の2つの条件に当てはまるものだけか
- [ ] 見本の文と、使わなかった見本の札・スクリプトが残っていないか（2-4 の8）
- [ ] 1332px 未満に縮めて、札が本文の下に並ぶか

### 印刷資料

- [ ] **白抜き文字（濃い地に白文字）を使っていないか**（背景が落ちると消える）
- [ ] 罫線が 0.5pt 以上あるか
- [ ] 淡い面が消えても意味が通るか（左罫とラベルが残るか）
- [ ] 人に配るなら本文が 12pt 以上あるか
- [ ] 1枚に収めるために縮小していないか
- [ ] **書き込む欄のある表・列の多い表が `class="grid"` になっているか**

## 7. やらない

- 情報を詰め込むために本文を小さくする（入らないなら分ける）
- 余白を埋めるためにカラム・罫線・装飾を足す（余白は残してよい）
- 「地味だから」と色・罫線・アイコンを足す（読めることが先。挿し絵は §5-5 の範囲で使ってよい）
- 白黒で作る（色を使う。これがこのスキルの前提）

## 8. 同梱ファイル

| ファイル | 中身 | いつ読む |
|---|---|---|
| `antipatterns.md` | アンチパターン集（デザイン／色／日本語／AI生成） | レビュー時・点検時 |
| `read-3col.html` | 読む資料のテンプレ（3カラム。左に目次、中央に解説、右に補足の札）。既定 | 読む資料を作るとき |
| `read.html` | 読む資料のテンプレ（2カラム。左に目次、中央に解説） | 右に置くものが1つも無いとき |
| `print.html` | 印刷資料のテンプレ（藍・朱） | |

`reading-load.py` は読む資料の地の文の読解負荷を測るスクリプト。自分の下書きにだけ使う。

## 9. トークンを変えたくなったら

色・フォントは各テンプレの `:root` に書いてある。
変えるときは対象モードのテンプレを直す。無彩色トークン（`--ink` `--ink-2` `--ink-3` `--line` `--tint`）は
どのテンプレも同じ値なので、変えるなら全ファイルを揃える。
`--rule` などに色を直接書かず、`:root` だけで完結させる。
